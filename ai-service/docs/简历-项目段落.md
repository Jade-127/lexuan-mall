## 乐选优品｜微服务电商 + LLM 智能客服（个人项目）

**技术栈**：Java 17 / Spring Boot 2.7 / Spring Cloud Alibaba(Nacos) / Gateway / OpenFeign / MyBatis-Plus /
MySQL / Redis / RabbitMQ ｜ Python 3.11 / FastAPI / LangGraph / pgvector / 阿里云百炼(qwen-plus)

**一句话**：在 Spring Cloud 微服务电商上，从零接入一个能查订单、答售后政策、走人工确认的客服 Agent。

### 后端（整站）

- 完成 9 个 Maven 模块的拆分与联调：Gateway 统一 JWT 鉴权与路由、Nacos 注册与配置、
  OpenFeign 服务调用、MyBatis-Plus 持久层；定位并修复 Feign 路径/HTTP 方法不匹配、
  `spring.factories` 三处重复键导致 `JsonConfig` 失效、19 位订单号在前端精度丢失等问题。
- 交易链路：下单扣减库存 → 支付回调经 RabbitMQ 异步更新订单状态；
  基于延迟消息 + 发布确认失败重试，处理超时未支付订单，避免消息丢失导致的状态不一致。

### 智能客服 Agent（Python，独立开发）

- 基于 LangGraph 实现 ReAct 工具调用 Agent，注册 5 个工具（商品检索 / 订单查询 / 订单详情 /
  售后政策 RAG / 建工单），多轮记忆用 Postgres checkpointer，`thread_id` 绑定「用户 + 会话」，
  服务重启后历史不丢。
- 设计「模型决策 + 代码兜底」的安全边界：`userId` 不进入模型上下文，由服务端上下文注入；
  会话归属校验（跨用户访问返回 403）；写操作经 `interrupt()` 人工确认后才落库，且副作用放在
  中断点之后，避免恢复重放时重复写入；按用户做滑动窗口限流（60s / 20 次）。
- 解决模型「凭记忆答政策」：评测发现 50% 的政策问题未检索知识库，改为在图中加入确定性前置检索
  节点（命中关键词先查库，把结果作为已完成的工具调用注入），准确率从 50% → 93%；
  并加出口校验，拦截「未调用工具却声称已建单」的假承诺。
- 自建 30 条评测集（售前 / 售中 / 售后各 10 条 + 负例），自动跑批并生成报告：
  工具选择准确率 93%、关键信息命中 100%、知识库召回 20/20、平均 2.9s / P95 5.3s。
- 可观测性与成本：请求级 trace（`trace_id` 贯穿检索→模型→工具→落库，可回放各阶段耗时）、
  工具调用统计（169 次真实调用，成功率 94%）、单轮成本 ¥0.0022（token 级埋点）。
- 客服以悬浮组件嵌入商城前端，复用现有登录态与 nginx 同源代理，避免二次登录与跨域改造。

## 面试可能被追问的三处（提前准备）

1. **为什么用 LangGraph 不用裸调 function calling？**
   记忆、中断恢复、多步循环都要自己写；LangGraph 的 checkpointer 直接给了状态持久化，
   `interrupt()` 直接给了人工确认，这两块自己实现至少多写 300 行。
2. **93% 怎么来的，剩下 7% 是什么？**
   30 条里错 2 条：模型偶尔跳过 `create_ticket`（波动，多轮均值 93%）。
   已用出口校验兜住「假承诺」，但根治需要 constrained decoding。
3. **成本 ¥0.0022 怎么算的？**
   `usage_metadata` 里取 input/output token，按 1000 次/天 × 平均 2571 / 65 token 估算；
   订单类问题比政策类贵一倍，因为要把订单数据塞回上下文。
